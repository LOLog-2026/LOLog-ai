# TTS 정확도 평가 계획

- 날짜: 2026-11-11
- 담당: 민주
- 이슈: #33
- 결과는 [README.md](README.md)에 적는다. 이 문서는 결과를 보기 전에 정한 기준과 절차다

## 1. 무엇을 확인하나

카드 영상(FR-EXT-02)은 대사를 화자 목소리의 TTS로 읽는다. Jetson 3호에 올리기 전에 세 가지를 확인한다.

1. **읽기**: 대사를 글자 그대로 읽는가. 빠뜨리거나, 다른 말을 하거나, 뜻 없는 말을 덧붙이지 않는가
2. **목소리**: 화자에게 붙인 목소리로 읽는가. 다른 화자 목소리나 다른 나이대·성별로 바뀌지 않는가
3. **길이**: 읽는 길이가 대사 길이에 맞는가. 끝없이 이어지지 않는가(길이 한도를 넣기 전 "ㅋㅋㅋ"에서 9분 넘게 멈췄다)

속도와 메모리는 따로 쟀다(README: Jetson 3호 rtf 5.35, 남은 메모리 최저 2.4GB).

## 2. 평가 대상

| 항목 | 값 |
|---|---|
| 모델 | `Qwen/Qwen3-TTS-12Hz-0.6B-Base` (클론). Jetson 3호에서 돌아가는 것을 확인한 모델 |
| 참조 음성 | 기본 화자 24명의 인사 클립(#27, "안녕하세요! 만나서 반가워요.") |
| 코드 | `src/lolog_ai/tts.py`의 `Tts.say` (워커가 쓸 코드 그대로. 낱자모 빼기, 길이 한도, 다시 읽기 포함) |

비교하는 방식은 두 가지다. 둘 다 같은 모델, 같은 대사, 같은 시드로 읽는다.

| 이름 | 방식 | 예상 |
|---|---|---|
| `icl` | 참조 음성의 소리와 글을 통째로 넣는다(기본값) | 목소리가 더 닮는다. 참조 음성의 내용(인사)이 대사에 섞일 수 있다 |
| `xvec` | 참조 음성에서 화자 벡터만 뽑아 넣는다 | 내용이 섞이지 않는다. 목소리가 덜 닮을 수 있다 |

## 3. 평가 대사 (`testset.json`, 144개)

`make_testset.py`가 고정 시드로 만든다.

| 묶음 | 개수 | 내용 |
|---|---|---|
| 짧음 | 30 | 2~6자. 감지 평가셋(#20)의 이야기 대사 |
| 중간 | 50 | 7~20자. 같은 곳 |
| 긺 | 40 | 21~40자. 같은 곳 |
| 어려움 | 24 | 직접 쓴 대사. 낱자모(ㅋㅋ·ㅠㅠ) 4, 숫자 4, 영어·외래어 4, 한 글자 대답 4, 느낌표·말줄임표 4, 반복 2, 아주 긴 대사(40자 이상) 2 |

- 목소리는 24명을 돌아가며 붙인다. 화자마다 6개씩 읽는다
- 대사마다 `text`(TTS에 넣는 글)와 `expect`(들려야 하는 말)를 둔다. 어려움 묶음은 둘이 다르다(`3시` → `세 시`, `ㅋㅋㅋ 웃겨` → `웃겨`)
- 일반 대사 120개로 합격을 판단하고, 어려움 24개는 따로 본다. 실제 카드에 얼마나 나올지 모르는 경우라 합격 기준에 섞지 않는다

## 4. 지표와 합격 기준

### 대사 하나의 통과

| 지표 | 재는 법 | 통과 |
|---|---|---|
| 읽기 | 읽은 소리를 Whisper(large-v3-turbo, 한국어)로 받아쓴다. 받아쓴 글과 `expect`에서 한글·영문·숫자만 남기고 글자 오류율(CER, 편집 거리 ÷ 글자 수)을 센다 | CER 10% 이하 |
| 목소리(묶음) | TTS 모델의 화자 인코더로 읽은 소리의 화자 벡터를 뽑아 24명 인사 클립의 벡터와 코사인 유사도를 잰다. 가장 가까운 클립이 같은 나이대·성별(예: `young-f`)이면 통과 | 같은 묶음 |
| 목소리(정확히) | 위에서 가장 가까운 클립이 자기 클립이면 통과 | 자기 클립 |
| 길이 | 소리 길이가 한도(읽는 글자 수 × 0.45초, 최소 4초) 안 | 한도 안 |
| 모두 | 읽기 + 목소리(묶음) + 길이 | 셋 다 통과 |

### 전체 합격 기준 (일반 대사 120개)

| 기준 | 목표 | 정한 이유 |
|---|---|---|
| 읽기 통과율 | 90% 이상 | 대사 10개 영상에서 틀린 대사가 평균 1개 이하 |
| 평균 CER | 5% 이하 | 통과한 대사도 한두 글자씩 자주 틀리면 안 된다 |
| 목소리(묶음) 통과율 | 95% 이상 | 아이가 어른 목소리로, 남자가 여자 목소리로 바뀌면 바로 티가 난다 |
| 목소리(정확히) 통과율 | 참고만 | 같은 묶음의 4명은 서로 비슷해서 틀려도 듣기에 큰 문제가 아니다 |
| 길이 통과율 | 100% | 하나라도 끝없이 이어지면 영상 작업이 멈춘다 |
| 다시 읽은 비율 | 10% 이하 | 다시 읽으면 시간이 그만큼 더 든다 |
| 오류로 멈춤 | 0건 | |

어려움 24개는 묶음별 통과율과 실패한 대사를 그대로 적는다.

## 5. 진행 순서

1. `make_testset.py`로 `testset.json`을 만든다
2. 3090에서 `eval_accuracy.py gen`으로 `icl`, `xvec` 두 방식을 각각 144개 읽힌다. 대사마다 걸린 시간, 소리 길이, 다시 읽은 횟수, 화자 벡터 결과가 `gen.json`에 남는다
3. `eval_accuracy.py score`로 받아쓰고 채점한다. `score.json`에 전체·묶음별·화자별 표와 대사별 결과가 남는다
4. 읽기에 실패한 대사를 귀로 듣는다. Whisper가 잘못 받아쓴 것(TTS는 맞게 읽음)과 TTS가 틀린 것을 나눠 적는다
5. 화자 24명마다 1개씩 듣고 목소리가 그림과 어울리는지 본다(사람이 할 일)
6. 결과를 README에 적고 아래 "결정"대로 정한다

```bash
P=/workspace/tts-voices/.venv/bin/python; V=/workspace/tts-voices/out/default-voices; R=/workspace/tts-eval
$P -I eval_accuracy.py gen $V $R/icl          && $P -I eval_accuracy.py score $R/icl
$P -I eval_accuracy.py gen $V $R/xvec --xvec  && $P -I eval_accuracy.py score $R/xvec
```

한 방식에 약 15분(읽기 12분 + 받아쓰기 3분)을 예상한다.

## 6. 결정

| 결과 | 할 일 |
|---|---|
| 한 방식만 합격 | 그 방식을 `tts.py` 기본값으로 한다 |
| 둘 다 합격 | "모두" 통과율이 높은 쪽. 2%p 안쪽 차이면 빠른 쪽 |
| 둘 다 읽기 불합격 | 실패 유형을 보고 순서대로 해 본다. ① 글 다듬기(숫자를 한글로, 기호 정리) ② `Qwen3-TTS-12Hz-1.7B-Base`로 같은 평가(Jetson 속도·메모리를 다시 재야 함) ③ 다른 TTS 모델 |
| 목소리(묶음) 불합격 | 어느 화자가 틀리는지 보고 그 화자의 인사 클립을 #27의 다른 후보로 바꾼다 |
| 길이 불합격 | 길이 한도와 다시 읽기 횟수를 고친다 |
| 특정 묶음(숫자, 영어 등)만 나쁨 | 콘티를 만들 때 대사를 한글로 풀어 쓰게 하거나 `speakable()`에서 바꾼다 |

## 7. 이 평가로 알 수 없는 것

- **Whisper의 한계**: 받아쓰기가 틀리면 TTS가 맞게 읽어도 실패로 센다. "응", "어?" 같은 한두 글자 대사는 받아쓰기가 특히 불안하다. 그래서 실패한 대사는 귀로 다시 확인한다(순서 4)
- **화자 벡터의 한계**: TTS 모델 자신의 화자 인코더로 재므로, 그 인코더가 못 가리는 차이는 잡지 못한다. 듣기에 자연스러운지, 감정이 맞는지도 재지 못한다(순서 5로 보완)
- **기기 차이**: 채점은 3090에서 한다. Jetson은 같은 모델·같은 코드지만 소리가 완전히 같지는 않을 수 있다. Jetson 3호가 다시 붙으면 `bench_clone.py`로 읽은 8개를 받아쓰기해서 3090과 비교한다
- **프로필 캐릭터**: 사진으로 만든 캐릭터는 기본 화자 목소리를 빌려 쓰므로 여기서 잰 24명 결과가 그대로 적용된다. 외모에 맞는 목소리를 골랐는지(`voice_for`)는 이 평가 범위가 아니다
